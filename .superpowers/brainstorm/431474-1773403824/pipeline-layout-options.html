A: Flat List + Badges

All videos in one list. Associated videos get an "ASSOC" badge. Filter dropdown to show All / Main / Associated. Existing batch buttons work on selection; new "Co-Segment" button activates only when associated videos selected.

Pros

  • Minimal architecture change
  • All existing selection/batch logic reuses
  • Quick to implement

Cons

  • Relationship between main↔associated not visually obvious
  • List gets 2x longer
  • Easy to accidentally select wrong video type for an operation

B: Session Groups

Videos grouped by session. Session header has checkbox (selects all videos in session). Each video shows its role (MAIN/DEPTH). Double-click a video to open its detail screen. Batch actions apply to selected sessions.

Pros

  • Familiar pattern in scientific software
  • Relationship immediately clear
  • Session-level selection natural for batch ops

Cons

  • Significant refactor of video list rendering
  • Need to derive/define "session" concept
  • Sorting/filtering gets more complex (sort sessions? videos within?)

C: Inline Expand

Main videos stay in the list as-is. Each card with an associated video gets a collapsible "1 associated" link that expands to show the depth video inline. Selection stays on main videos — batch ops like "Co-Segment" derive associated videos from selection.

Pros

  • Main list unchanged for videos without associations
  • Relationship clear when expanded
  • Selection model stays simple (select main videos)
  • Moderate refactor — mostly card-level changes

Cons

  • Expand/collapse adds interaction complexity
  • Less discoverable than always-visible
  • Doesn't scale well to 1:many if you ever need it
